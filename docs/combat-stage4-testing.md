# 第四阶段：第一人称持物回弹

版本：`0.2.0-combat.4`。第三阶段收到用户“测试通过”的反馈；未提供逐项场景，因此不扩大为所有模组／光影条件均已验证。

延续用户指定的交付流程：本轮仅编译打包、静态审查与发行文件核对，不运行单元测试、游戏 QA 或 CI 测试，不改测试实例。以下步骤供用户执行，尚未标记通过。

## 新功能

收到有效近战命中确认后，第一人称持有物品增加一个很短的回弹倾角。默认最大 3°，15 ms 快速进入，其余时间恢复，总时长 120 ms；连续有效命中从当前角度衔接，幅度不累加。

只在持物模型的渲染矩阵内旋转，不写入挥动进度、装备进度、攻击计时、相机角度、实体位置或伤害数据。不冻结输入，不增加攻击冷却，也不改变格挡规则。已有准星、粒子、怪物模型反应保留。

同一帧各层贴图与附魔渲染使用同一个回弹采样值，避免分层物品每层加倍。该效果是原创视觉增强，不宣称现代 Minecraft 原版存在同样的回弹机制。

## 安装与设置

关闭游戏，停用旧 LegacyVisualFix JAR，放入第四阶段 JAR，只保留一个启用版本。原 combat.cfg 保留，启动会补齐字段。单机直接安装；多人建议两端同版，仍沿用协议 v1。

`config/legacyvisualfix/combat.cfg` 的 client 分类，修改后重启：

| 字段 | 默认 | 范围／用途 |
| --- | --- | --- |
| weaponRecoil | true | 独立开关，关闭不影响前三阶段反馈 |
| recoilDegrees | 3.0 | 0–5°；0 关闭可见回弹 |
| recoilDurationMs | 120 | 60–240 ms；只控制表现时长 |

## 触发范围与保守匹配

协议 v1 没有攻击事务／武器 ID，因此不能精确证明每个迟到回包属于哪一把武器。实现只接受最近 250 ms 内记录的本地攻击，要求目标对象、维度、当前快捷栏位置、物品类型及子类型仍匹配。每条本地攻击记录最多触发一次回弹。

目标被移除、反馈过迟、未经过本地 AttackEntityEvent、换槽或换物品时可能没有回弹；准星、粒子、怪物反应继续按各自规则工作。这是优先少显示一次的保守取舍，不能把回弹当作精确的武器命中审计信息。相同类型、同槽位的极快替换及短时间同目标重复攻击仍无法靠 v1 完全区分事务。

进食、喝药、拉弓、格挡期间、打开界面、第三人称、非玩家相机、玩家死亡／隐形时跳过并清理回弹。空手、地图没有此效果。普通持物近战不限于 ItemSword，可包括 GT、匠魂及其他工具；非武器持物攻击也可能显示回弹。

## 手动测试步骤

1. **基本效果**：第一人称拿铁剑攻击牛或僵尸。观察有效命中后武器短促回弹；空挥、挖方块不应触发这项效果。可临时设 recoilDegrees=5、recoilDurationMs=220 便于录屏慢放。
2. **连续攻击**：不断点击，确认挥动不会被卡住、暂停或拉长；无敌帧内的无效攻击不应每次制造回弹。停手后应迅速恢复原轨迹。
3. **开关对照**：weaponRecoil=false 后重启，确认仅第一人称回弹消失，伤害、怪物击退、粒子和第三阶段模型倾斜不变。
4. **切换与使用**：命中后马上换槽、切空手、打开背包、切第三人称，观察是否残留；尝试剑格挡、拉弓、食物与药水，确认使用动作正常。
5. **模组物品**：分别试 GT 钢制小刀、匠魂铁大剑和附魔剑。检查贴图各层、附魔光效与持物模型是否一起运动；Backhand 副手另外核查是否误跟随主手回弹。
6. **怪物与光影**：对 Special Mobs、神秘时代、Ender Zoo、暮色森林普通怪物测试；Photon 开启／关闭分别观察武器和模型，不把光影差异误当作伤害或击退变化。
7. **生命周期与网络**：退出重进、换维度、死亡后应无残留。多人延迟较大时允许回弹缺失，但不应产生持续倾斜或影响攻击操作。

## 兼容范围（尚待本阶段实测）

| 范围 | 实现边界 |
| --- | --- |
| 怪物模组 | 沿用已有服务端伤害确认；没有新增怪物白名单。前三阶段样本不构成本阶段逐项验收 |
| 原版与 Forge 持物 | 钩子位于 ItemRenderer 的 Forge 四参数 renderItem 方法，限定 EQUIPPED_FIRST_PERSON；可覆盖走此路径的普通及 IItemRenderer 自定义模型 |
| GT / TiC | 未硬编码武器类，预期能接入标准持物路径；特殊渲染或替换路径需用户验证 |
| Backhand | 对安装的 1.8.14 做了静态路径检查，副手渲染临时切换槽位，槽位匹配可隔离主手回弹；主／副手、物品使用与切换行为未实际验证，不承诺所有副手动作支持 |
| 旧装备模型 | 仅渲染对象与当前持有 ItemStack 是同一对象时应用；服务端同步替换 ItemStack、装备过渡可能跳过短回弹 |
| 覆盖渲染的模组 | 完全替换标准 renderItem 且不走父方法时可能没有效果；调用点缺失时允许退让，保留其他反馈 |
| Photon / 多层与附魔 | 已按同帧一致性与矩阵范围实现防护，但本轮未运行游戏验证 |

若有问题，可先关闭 weaponRecoil 保留前三阶段功能。反馈请附武器、目标、主／副手、是否开 Photon、异常动作和日志；若只是看不明显，也可说明当前幅度及录屏结果。

# 第三阶段：定向模型受击反应

版本：`0.2.0-combat.3`。按用户要求，本轮只进行编译打包和静态代码审查，不运行单元测试、游戏、实机 QA 或 CI 测试。第二阶段的测试结果不能视为本阶段通过测试的证据。

## 本次变化

沿用协议 v1 的服务端确认消息。去重后的有效近战损失触发局部粒子、准星提示，并给目标模型一个短暂的定向倾斜。吸收生命损失也可触发；没有实际损失的挥动不凭空触发成功反馈。

默认最大 3°，前 20 ms 快速倾斜，随后平滑恢复，总时长 140 ms。方向根据收到消息时客户端玩家与目标的水平位置估算，模型上半部向远离攻击者的方向倾斜；不是服务端提供的精确接触法线。连续有效命中从当前姿态衔接，不累加到超过幅度上限。

本阶段是原创视觉增强，并非现代原版统一受击动画的回移植。整体模型绕渲染原点倾斜，不是单独给胸部骨骼制作动画。原有受伤变红、步行动画和真实击退继续由游戏决定。

实现只在原生生物渲染矩阵内增加旋转：没有写入实体坐标、速度、朝向、模型字段、hurtTime、hurtResistantTime 或 AI；没有攻击冷却、硬直、镜头震动、范围伤害。普通护甲／手持物所在渲染阶段跟随模型；名字、血条插件和碰撞箱不主动旋转。

## 安装

1. 关闭游戏，将旧 LegacyVisualFix JAR 移出 mods 或改为 `.disabled`。
2. 放入 `legacyvisualfix-0.2.0-combat.3.jar`，只启用一个版本。
3. 正常启动实例，配置会自动增加新字段。无需删除旧 combat.cfg。

单机只需实例安装；多人建议两端同版。协议未升级，与前两阶段沿用相同命中消息；没有服务端支持时不会猜测成功命中。新效果仅攻击者本人可见。

本轮未替换用户实例中已安装的第二阶段 JAR，也未改变实例配置或存档，由用户决定安装和测试。

## 配置

文件 `config/legacyvisualfix/combat.cfg` 的 client 分类，修改后重启。

| 字段 | 默认值 | 用途 |
| --- | --- | --- |
| modelReaction | true | 单独关闭本阶段模型反应，不关闭粒子或准星提示 |
| reactionDegrees | 3.0 | 最大倾斜角度，0–4°；0 表示无倾斜 |
| reactionDurationMs | 140 | 反应时长，80–300 ms，不改变战斗计时 |
| reactionExcludedEntities | 空列表 | 精确实体注册名或完整 Java 类名，不支持通配符 |

排除某个实体的 Forge 配置示例：

```text
S:reactionExcludedEntities <
    Thaumcraft.BrainyZombie
    toast.specialMobs.entity.zombie.EntityBrutishZombie
 >
```

## 建议按顺序测试

1. **普通目标**：白天用空手或低伤害武器攻击牛、僵尸。从正面、侧面、背面分别攻击，观察模型是否短暂远离你倾斜并恢复。效果只有 3°，可录屏慢放；需要延长观察可暂设 reactionDurationMs=250、reactionDegrees=4。
2. **连续攻击**：持续点击，观察有效命中时是否自然衔接；无敌帧中的无效挥动不应每次追加倾斜，不应越打越歪。停止后模型恢复原状。
3. **开关对照**：modelReaction=false 后重启，比较相同武器和怪物。仅新倾斜消失，旧击退、变红、粒子和准星反馈应保留。可用 F3+B 确认碰撞箱没有跟随视觉倾斜。
4. **模组怪物及装备**：用 GT 钢制小刀、匠魂武器攻击 Special Mobs 普通僵尸、神秘时代僵尸、Ender Zoo 骑士和暮色森林头盔蟹。留意护甲、手持物、发光层与身体是否错位，以及横向来袭方向是否正确。
5. **例外与清理**：击杀、切换维度、退出重进后应无残留倾斜。玩家、Boss、骑乘／载客实体及大模型应保持原有姿态。命中后突然隐形也应停止额外倾斜。
6. **光影与界面**：分别开启／关闭 Photon，观察模型及阴影是否异常；名字和血条不应随新效果倾斜。若某个实体异常，先加入排除名单复测，也可关闭 modelReaction 保留前两阶段效果。

建议反馈：目标注册名或截图、使用武器、是否开 Photon、是否只在第三阶段出现，以及异常表现（歪斜方向、护甲分离、名字倾斜、无法恢复、崩溃）。若崩溃请附对应 crash-report 或日志。

## 兼容边界：本阶段尚未实测

| 范围 | 当前实现与限制 |
| --- | --- |
| 标准生物渲染器 | 目标为 EntityLivingBase，且渲染经过 RendererLivingEntity.doRender 的 rotateCorpse 调用时可以应用；不使用原版怪物白名单 |
| 模组渲染覆盖 | 继承标准路径的渲染器预期可接入；完全自定义渲染、覆盖 doRender 且不调用父方法者可能无新效果 |
| Special Mobs / Thaumcraft / Ender Zoo / Twilight Forest | 普通生物是优先验证对象；第二阶段伤害兼容样本不能证明第三阶段模型兼容 |
| 默认跳过 | EntityPlayer、IBossDisplayData、骑乘／载客实体、死亡或隐形目标；高度大于 4 或宽度大于 3 的实体 |
| 大型与 Boss | 不强行旋转；自定义 Boss 若没有实现 IBossDisplayData 且尺寸较小，需手动加入排除名单 |
| 附加渲染层 | 父类内的护甲／手持物跟随矩阵；在该方法外另行渲染的附件、插件血条、拖尾等不保证跟随 |
| 探测范围 | 跳过客户端缺失、坐标无效、距离超过 16 格或生成反应时被遮挡的目标 |
| 服务端／多人 | 伤害协议和服务端实现未改；独立服务器、多人延迟、其他动画模组和 Photon 渲染兼容仍待本阶段验证 |

渲染注入允许在调用点被其他模组替换时不生效，而不强制因缺少该调用点中止启动；这时仍可保留准星／粒子。维护者不能把这种兼容退让当成模型反应已运行的证据。
